## 已适配的破坏性变化

| 上游变化 | Android 行为 |
| --- | --- |
| `GET /bots/{bot}/agents/{id}/codex/usage` 删除，改为 `GET /bots/{bot}/agents/{id}/quota` | `BotApi.agentQuota` 指向新路径。响应结构未变（`limit_reached`、`windows[used_percent, window_minutes, resets_at]`），`CodexUsage` 模型不变。旧服务端仍只有旧路径，因此该功能在旧版服务端不可用。 |
| ChatGPT / Grok 账号登录移入 Agent 工作区，Memoh 不再解析或保存凭据 | 额度与「已连接」判定不再要求 `agent_credential_id`。设备登录（`/login/device/{authorize,poll,cancel}`）本就产不出凭据，此前这些 Agent 会一直显示「待配置」。 |
| `POST /agent-authorizations/{id}/poll` 删除 | 改为 `GET /agent-authorizations/{id}`。旧服务端只有 `/poll` 会推进授权状态且 GET 为纯读，因此读取后仍为 pending 时回退一次 `/poll`；该路由返回 404 即判定为新服务端并停止回退。 |
| `agentcredential.Authorization` 移除 `interval_seconds`、`user_code`、`verification_url` | 轮询固定 5 秒。授权弹窗仅在存在 `user_code` 时显示代码块，Claude 浏览器授权只显示说明与按钮。 |
| `POST /agent-authorizations` 不再接受 ChatGPT 账号的 staged 授权 | 新增授权只接受 API key 与 Claude OAuth。Codex 设备登录接口返回 404 时沿用既有 staged 回退，供尚未部署设备登录的旧服务端使用。 |
| `createSessionRequest` 移除 `acp_runtime_id` | 客户端未使用该字段，无需改动。 |

## 未接入

未读状态与系统通知（`GET /users/me/unread`、`PUT /users/me/read-state`、`GET /users/me/attention/events`）本轮不实现。服务端只提供 SSE，客户端需自行渲染通知；上游设计文档将离线推送（Web Push / Service Worker）列为非目标，仓库中也没有 Web Push、FCM、APNs 实现。`session.Session` 新增的 `unread` 等字段为可选，不读取不影响现有会话列表。

## 无需客户端动作

压缩由覆盖层改为 history checkpoint（`0170_history_checkpoints` 迁移）、外部 Agent 进程管理重构、会话未读与通知、DeepSeek 搜索 provider、Telegram 流式限速按 bot 计算，均由服务端实施。ACP runtime 管理接口（`/bots/{bot}/acp-runtimes/*`）整体移除，客户端使用的是会话级 `/sessions/{id}/acp-runtime`，未受影响。
